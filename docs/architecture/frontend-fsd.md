# Frontend FSD

Документ фиксирует локальные правила применения FSD в `apps/frontend`.

Полное описание методологии, базовых слоев, public API и стандартных
ограничений следует брать из скилла `feature-sliced-design`.

Если скилл не установлен, то локальные файлы можно найти по ссылке
[`docs/ai/tooling/skills/feature-sliced-design`](../ai/tooling/skills/feature-sliced-design/SKILL.md).

Если рекомендации скилла конфликтуют с этим документом, для данного проекта
приоритет у этого документа.

## Общий подход

- Frontend строится по FSD с практическими упрощениями.
- По умолчанию агент должен опираться на скилл `feature-sliced-design`.
- Этот документ задает проектные отклонения от канонического FSD.

## Предпочтительная структура

- Основной сценарий для нового кода: `app`, `pages`, `entities`, `shared`.
- Слой `widgets` допустим, когда появляется действительно крупный
  переиспользуемый блок композиции.
- Слой `features` не запрещен, но в этом проекте не является предпочтительным.
- По умолчанию пользовательские сценарии и взаимодействия следует оставлять в
  `pages` или, если это оправдано доменной моделью, в `entities`.
- Выделять `features` следует только тогда, когда это действительно упрощает
  структуру, а не делает ее сложнее.

## Импорты внутри entities

- В этом проекте прямые cross-imports между slice внутри `entities` разрешены.
- Если зависимость между `entities` оформлена через `@x` или другой
  рекомендованный документацией FSD способ, это тоже допустимо.
- При выборе между прямым импортом и `@x` следует исходить из читаемости и
  простоты поддержки текущего кода.

## Переиспользование UI

- Компоненты, которые должны быть общими для нескольких приложений или частей
  системы, не следует дублировать в `apps/frontend`.
- Такой UI следует выносить в `packages/ui-kit` и использовать как
  workspace-пакет.

## Именование

- Папки slice и segment именуются в `kebab-case`.
- React-компоненты, providers и UI-компоненты именуются в `PascalCase`.
- Переменные и функции именуются в `camelCase`.
- Хуки именуются в `camelCase` и обязательно начинаются с `use`.
