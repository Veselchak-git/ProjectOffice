# Правила backend-модулей

Документ фиксирует базовые соглашения для backend в `apps/backend`.

## Структура модулей

- Каждый доменный модуль должен находиться в `apps/backend/src/modules/<kebab-case>/`.
- У каждого модуля должен быть `index.ts` как точка входа.
- Базовая структура модуля:
  - `index.ts` — регистрация модуля и публичная точка входа
  - `controller.ts` — маршруты Fastify и обработчики
  - `service.ts` — бизнес-логика
  - `schema.ts` — схемы запросов и ответов
- `repository.ts` добавляется только тогда, когда модуль работает с Prisma или другим источником данных.

## Именование

- Имя папки модуля должно быть в `kebab-case`
- Имя папки модуля, route prefix и имя Fastify-плагина должны быть согласованы по смыслу и стилю.
- Не допускается смешивать разные варианты имени одной и той же сущности без причины.

## Границы модулей

- Регистрация всех модулей выполняется только через `apps/backend/src/modules/index.ts`.
- Общие утилиты, ошибки, route-константы и инфраструктурный код не должны храниться внутри доменных модулей.
- Общий backend-код размещается в:
  - `src/shared` — инфраструктура и переиспользуемые утилиты
  - `src/schemas` — общие DTO и TypeBox-схемы
- Если несколько модулей используют один и тот же контракт или helper, его нужно вынести в `shared` или `schemas`.
- Следует избегать прямой зависимости одного модуля от приватной реализации другого модуля.

## API и валидация

- Каждый новый или измененный endpoint должен иметь явные схемы запроса и ответа.
- Конфигурация маршрута должна быть совместима с валидацией Fastify.
- Для нового или измененного endpoint нужен как минимум один тест на основной успешный сценарий.

## Prisma и плагины

- Изменения в `prisma/schema.prisma` должны сопровождаться миграцией.
- Если меняется поведение, завязанное на данные, нужно обновить тесты и seed-данные, если это необходимо.
- Fastify-плагины должны оформляться через `fastify-plugin`.
- Для Fastify-плагинов нужно задавать явное имя.
