# ТЕХНИЧЕСКОЕ ЗАДАНИЕ на разработку системы отслеживания ошибок

## Назначение системы

Система предназначена для регистрации, учёта, классификации, назначения и отслеживания жизненного цикла дефектов (багов), задач и запросов на доработку программного обеспечения в рамках проектной деятельности организации.

## Модули

Все модуль указаны без взаимосвязей

### Пользователи

- логин(обязательное)
- пароль(обязательное)
- глобальная роль(обязательное)(админ или пользователь)


### Роли в проекте

- Наблюдатель (Viewer) Только просмотр, аудит лог не видит
- Репортёр (Reporter) Создание задач - может создать задачу с статусом new, аудит лог не видит
- Обновляющий (Updater) Изменение задач - может менять задачу, аудит лог не видит
- Разработчик (Developer) Назначение, решение задач - может перевести задачу из assigned в resolved и добавить решение к задаче, аудит лог не видит
- Менеджер (Manager) Управление проектом - может создавать новые проекты + управлять задачами в проекте + аудит лог
- Администратор (Administrator) Полный доступ - может создавать новых пользователей + имеет доступ ко всему

Роли назначаются для каждого пользователя и проекта отдельно.

### Проекты

- Наименование (обязательное)
- описание
- статус (активный/архивный)(обязательное)
- версии продукта (обязательное)

### Задачи (Issues)

- название (обязательное)
- проект (обязательное)
- категория (обязательное)
- приоритет (критичный / серьёзный / незначительный / общий вопрос)(обязательное)
- Воспроизводимость (всегда / иногда / случайно / не воспроизводится / не пробовал)
- Версия продукта (обнаружена в версии)
- описание
- Дополнительная информация
- статус (обязательное)
- дата создания (обязательное)
- дата редактирования (обязательное)
- назначена на (пользователь)
- решение задачи - описание решения

### Статусы задач в проекте

- Новая (new)
- Подтверждена (acknowledged)
- Принята в работу (confirmed)
- Назначена (assigned)
- Решена (resolved)
- Закрыта (closed)

матрица переходов любая (для учебного проекта)

### Audit-log

- тип события (обязательное) - список всех возможных событий
- subjectType - кто совершил действие (обязательное)
- objectType - над чем совершено действие (обязательное)
- subjectId - id кто совершил действие (обязательное)
- objectId - id над чем совершено действие (обязательное)
- old? - старые данные
- new? - новые данныее

## Экраны системы

### Старница логина

1. вход в систему по логину и паролю
2. показ ошибки при неверном пароле

### Общий лайаут

1. должен содержать навигацию согласно правам
2. кнопка выхода
3. кнопка редактирования своего профиля (смена пароля)
4. смена темы
5. смена языка

### Главная страница с виджетами проектов и задач
1. Виджеты с информацией по задачам в проектах
2. Виджеты назначенных на пользователя задач

### старница со списком проектов

1. табличное представление списка проектов - сортировка, фильтрация, изменение колонок, изменение видимости колонок
2. переход на станицу деталей проекта
3. кнопки по созданию нового проекта, редактированию существующего (при наличии прав)

### старница со списком задач

1. табличное представление задач - сортировка, фильтрация, изменение колонок, изменение видимости колонок
2. переход на станицу задач
3. кнопки по созданию задач, редактированию существующей (при наличии прав) - разные пункты доступны разным ролям

### старница со списком пользователей (администратор)

1. табличное представление задач - сортировка, фильтрация, изменение колонок, изменение видимости колонок
2. создание пользователей

### старница с аудит логом событий (администратор+Менеджер)

табличное представление задач - сортировка, фильтрация, изменение колонок, изменение видимости колонок

### страницы конкретной задачи или проекта

1. список полей текущей сущности
2. кнопка редактирования сущности при наличии прав

## Функциональные требования
1. соблюдение ролевой модели как на стороне клиента так и на стороне бекенда - пункты которые не доступны роли не отображаются + при попытке вызвать API возвращают ошибку
2. авторизация по средством jwt токена (только access токен, refresh token опционально)
3. смена языка
4. смена темы
5. соблюдение контрастности цветов
6. табличные данные нужно уметь выгружать в excel (отдельный backend-for-frontend) с учетом локализации и временной зоны
